# 简递 · 版本更新发布指南

整套机制只有两个文件：**一个 JSON 清单 + 一个安装包**。
现在默认托管在阿里云 OSS（`jiandidi`，华南1 深圳），发布脚本一条命令就传上去。

---

## 一、它是怎么工作的

1. 客户端启动 4 秒后、以及之后每 10 分钟，向「更新源」请求一份 `latest.json`；
2. 清单里的 `version` 比当前版本新 → 弹窗（可选更新可以「稍后」，强制更新关不掉窗口）；
3. 用户点「立即更新」→ 流式下载 → 校验大小和 SHA256 → 启动安装向导 → 程序自动退出；
4. 装完向导自动重新打开程序。

客户端只认「版本号变大」，所以**版本号必须递增**（1.0.0 → 1.0.1 → 1.0.2）。

OSS 上的目录结构：

```
jiandidi/
├── latest.json                                   ← 清单（每次发布覆盖）
└── releases/
    ├── 简递-Setup-1.0.1.exe                      ← 当前版本
    └── 简递-Setup-1.0.0.exe                      ← 旧版本，留着方便回滚/手动下载
```

对应地址：

```
https://jiandidi.oss-cn-shenzhen.aliyuncs.com/latest.json
https://jiandidi.oss-cn-shenzhen.aliyuncs.com/releases/简递-Setup-1.0.1.exe
```

## 二、怎么访问这个 OSS（三条路，选一条）

| 方式 | 需要什么 | 适合 |
|---|---|---|
| **A. 发布脚本直传**（本目录 `发布更新.mjs --oss`） | 一对 AccessKey，填进 `oss.config.json` | 日常发版，一条命令搞定 ✅ |
| B. 官方命令行 `ossutil` | 装 ossutil，配 `ossutil config` | 想批量同步、删旧版本 |
| C. 控制台手动拖 | 无 | 偶尔发一次，懒得配 |

三种方式本质上都是用 AccessKey 调 OSS 的 REST 接口。本目录已经内置了一个**零依赖的 OSS 客户端**（`oss.mjs`），
签名算法是 OSS V4（`OSS4-HMAC-SHA256`），已和官方 SDK 逐个字段比对过，不需要 `npm i` 任何东西。

## 三、一次性配置（只做一次）

### 1. 建一个只用得上「上传」的子账号

**不要用主账号的 AccessKey**（主账号权限太大，泄露等于整个云账号交出去）。

控制台 → 访问控制 RAM → 用户 → 创建用户：

- 勾选 **OpenAPI 调用访问**（会生成 AccessKey ID / Secret，Secret 只显示一次，复制下来）
- 不要勾「控制台访问」

然后给这个用户授权：**自定义策略**，粘贴下面这段（把 bucket 名换成你的）：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "oss:PutObject",
        "oss:PutObjectAcl",
        "oss:GetObject",
        "oss:ListObjects"
      ],
      "Resource": [
        "acs:oss:*:*:jiandidi/latest.json",
        "acs:oss:*:*:jiandidi/releases/*"
      ]
    }
  ]
}
```

- `oss:PutObject` 上传，`oss:PutObjectAcl` 设置对象为公共读，`oss:GetObject` 上传后自检
- 只授权 `releases/*` 和 `latest.json`，这个账号**碰不到桶里别的东西**

### 2. 填 `oss.config.json`

把 `oss.config.example.json` 复制一份改名 `oss.config.json`：

```json
{
  "accessKeyId": "LTAI5t................",
  "accessKeySecret": "................................",
  "bucket": "jiandidi",
  "region": "cn-shenzhen",
  "dir": "releases",
  "endpoint": "",
  "acl": "public-read"
}
```

> `region` 写 `cn-shenzhen` 或 `oss-cn-shenzhen` 都行（脚本会自动归一）。
> `endpoint` 留空就用默认域名；以后挂了 CDN / 自定义域名（比如 `dl.jiandi.cn`）填这里，
> 清单里的下载地址会自动变成那个域名。

**这个文件是你的钥匙，别发给别人，别放进截图，别提交到 Git。**

### 3. 检查

```bat
node 发布更新.mjs --check
```

```
  简递 · OSS 配置检查
    配置文件   C:\...\发布工具\oss.config.json
    Bucket     jiandidi
    区域        cn-shenzhen
    接入地址   https://jiandidi.oss-cn-shenzhen.aliyuncs.com
    AK         LTAI5t****Xy9z

  ✔ 凭证有效，可以上传
```

## 四、以后每次发版（一条命令）

```bat
cd 投递工具\发布工具

node 发布更新.mjs --exe="..\安装包\简递-Setup-1.0.1.exe" --version=1.0.1 ^
  --notes="修复登录失效后不继续的问题|广西人才网支持学历筛选" --oss
```

跑完长这样：

```
  简递 · 发布更新  v1.0.1  【可选】

  计算校验值... 完成
    安装包  简递-Setup-1.0.1.exe  108.2 MB
    SHA256  2464381ef7befb037818ff4ae4530ce8…

  ✔ 本地清单已生成：..\安装包\latest.json

  上传安装包... 100%   108.2 MB / 12.4s
    https://jiandidi.oss-cn-shenzhen.aliyuncs.com/releases/简递-Setup-1.0.1.exe
  上传清单... 完成
    https://jiandidi.oss-cn-shenzhen.aliyuncs.com/latest.json

  验证外网可访问... 正常
```

参数：

| 参数 | 作用 |
|---|---|
| `--oss` | 生成清单后直传 OSS（不加就只生成本地文件） |
| `--force` | **强制更新**：弹窗没有「稍后」和「跳过」，窗口关不掉 |
| `--min=1.0.0` | 低于这个版本的客户端一律强制更新（发安全补丁时用） |
| `--notes="A\|B"` | 更新说明，`\|` 分隔成多行 |
| `--dry-run` | 全流程演练，打印将要上传的地址但不真传 |
| `--check` | 只检查凭证和连通性 |
| `--dir=releases` | OSS 上存放安装包的目录 |
| `--endpoint=域名` | 临时指定自定义域名 / CDN |
| `--acl=public-read` | 对象权限，默认公共读 |

速度参考：108MB 安装包在家庭宽带上约 10~40 秒，脚本内置 5xx 自动重试 2 次。

客户端**不用动**：内置地址已经是 `https://jiandidi.oss-cn-shenzhen.aliyuncs.com/latest.json`，
正在运行的老客户端最迟 10 分钟内就会收到弹窗。

## 五、权限：用户端凭什么能下载

OSS 桶默认是**私有**的，匿名访问会 403。发布脚本上传时会顺手把这两个文件设成「公共读」
（`x-oss-object-acl: public-read`），所以只要桶没开「阻止公共访问」，用户端就能直接下。

发布脚本最后那步 `验证外网可访问` 就是在替你验这件事：

- 输出 `正常` → 搞定，谁都下得到
- 输出 `被拒绝（403）` → 文件传上去了但下不了，按提示改：

**改法 A（最快）**：控制台 → `jiandidi` → 读写权限 → 设为「公共读」。
整个桶都能被匿名读，但桶里只有安装包，问题不大。

**改法 B（更精细，推荐）**：桶保持私有，加一条 Bucket 授权策略，只放开发布目录：

控制台 → `jiandidi` → 权限控制 → Bucket 授权策略 → 编辑，粘贴：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": ["*"],
      "Action": ["oss:GetObject"],
      "Resource": [
        "acs:oss:*:*:jiandidi/latest.json",
        "acs:oss:*:*:jiandidi/releases/*"
      ]
    }
  ]
}
```

**改法 C**：上传时 `--acl=private` 保持私有，另找 CDN 回源（要配私有回源，麻烦，不推荐）。

> 还有个小坑：桶如果开了「阻止公共访问」，上面的 A/B/C 都会失效，去权限控制里关掉它。

## 六、客户端怎么找到更新源

优先级从高到低（装好的程序不用改任何东西，默认走第 3 条）：

1. 环境变量 `JIANDI_UPDATE_URL`（调试用）
2. 程序目录下的 `update-source.json`

   ```json
   { "url": "https://jiandidi.oss-cn-shenzhen.aliyuncs.com/latest.json" }
   ```

3. `简递数据/config.json` 里的 `updateUrl`
4. **内置默认**：`https://jiandidi.oss-cn-shenzhen.aliyuncs.com/latest.json`

想临时换源又不想重新打包，就用第 1 或第 2 条。

## 七、自测（不占 OSS 流量）

```bat
:: 1) 起一个本地更新源（--slow 用来模拟慢速网络，方便看进度条）
node 本地更新服务.mjs --dir="..\..\_build\test-update" --port=8931 --slow=25

:: 2) 用环境变量把客户端指过去
set JIANDI_UPDATE_URL=http://127.0.0.1:8931/latest.json
"..\桌面版\简递.exe"
```

- 想看**可选更新**：清单不带 `--force`
- 想看**强制更新**：清单带 `--force`，此时点 × 会被拦下并提示「请先完成更新」

测完记得清掉 `简递数据/update_state.json` 里的 `skippedVersion`，否则被跳过的版本不再弹窗。

## 八、常见错误

| 提示 | 原因 | 怎么办 |
|---|---|---|
| `SignatureDoesNotMatch` | Secret 抄错、多空格，或电脑时间不准（差 15 分钟以上） | 重新复制 Secret；Windows 设置里同步时间 |
| `InvalidAccessKeyId` / `NoSuchBucket` | AK 写错，或 AK 不属于这个账号 | 换正确的 AK；确认桶名是 `jiandidi` |
| `AccessDenied`（上传时） | 子账号没 `oss:PutObject` / `oss:PutObjectAcl` | 按第三节的策略重新授权 |
| `被拒绝（403）`（自检时） | 桶私有，或开了「阻止公共访问」 | 见第五节 A/B |
| `上传中断：ECONNRESET` | 网络抖动 | 脚本自动重试 2 次；还不行就重跑，OSS 支持覆盖上传 |

## 九、注意事项

- **`latest.json` 一定不缓存**：脚本已给它设 `Cache-Control: no-cache, no-store`，别手动改。
- **安装包不要改名后再改清单**：`sha256` / `size` 必须对应同一个文件，改了就重跑一次发布脚本。
- **不要回退版本号**：客户端只认更大，回退不会触发更新。
- **旧版本别急着删**：`releases/` 里的老安装包留着，用户手动重装、回滚都用得上；一个 108MB 文件一个月也就几毛钱。
- **AccessKey 泄露的后果**：别人能往你桶里上传、覆盖 `latest.json`，等于能给你的用户下发任意安装包。**一旦发现泄露，立刻在 RAM 里禁用该 AK 并新建一个。**
- **强制更新要有退路**：下载源挂了用户就卡住了，务必保证 OSS 地址长期有效（OSS 不比自建服务器，这点基本不用担心）。
